# Contributing to Jilva

Thanks for your interest. Jilva is early — right now thoughtful feedback matters more than code.

## Ground rules

1. **Discuss before building.** Open a Discussion or RFC issue for anything beyond a typo. Unsolicited large PRs will be closed.
2. **Small, reviewable PRs.** One change per PR. Include why, not just what.
3. **No generated noise.** Do not bulk-open AI-generated issues/PRs.
4. **Respect scope.** `jilva-rs` is in design — API PRs are not accepted until RFCs are approved.

## How to help now

- Review open RFCs in `jilva-rs` — point out flaws, edge cases, prior art.
- Improve docs and examples of intent (diagrams, API sketches).
- Report confusing wording in README/docs as `docs` issues.
- Share real-world TUI pain points (with context, not just feature votes).

## Issues

- Search existing issues/Discussions first.
- Use the templates: Bug, Feature, Docs.
- One problem per issue. Include version/commit, OS, terminal, reproduction steps.

## Pull requests

- Branch from `main`: `feat/<short>`, `fix/<short>`, `docs/<short>`.
- Follow Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`.
- Update docs if behavior or wording changes.
- CI must pass. Add tests when code lands (none required for docs-only PRs).

## Code of Conduct

By participating you agree to our [Code of Conduct](./CODE_OF_CONDUCT.md). Be direct, be kind, assume good intent.
